# Chapter and section mind maps

The TOC shows a mind-map icon beside every entry. Saved maps use a green highlighted icon with a check badge; ungenerated entries retain the neutral outline. A single owned-book status index request populates the TOC on open and refreshes on tab focus, with short polling only while known tasks are running. Generation completion updates the matching icon immediately, even if the dialog was closed during generation. Status reads return navigation targets only, include R2-recovered results, and never invoke AI. The title remains the navigation button. Clicking the icon opens an accessible dialog that fills the reading viewport by default (with safe-area padding for mobile controls); first use generates from the owned original EPUB, later openings (including another browser/device) read the stored result. Branches collapse/expand individually or with the toolbar’s all-node controls. The canvas supports free drag-to-pan from blank space or nodes, trackpad two-finger scrolling to pan, pointer-anchored pinch (or Ctrl/⌘ + wheel) zoom, single-finger pan and two-finger touchscreen pinch/pan. Within the map, unmodified scrolling always pans, including fast integer pixel deltas; no device guess based on delta magnitude. The reading desk uses unmodified scrolling to pan on Mac (both trackpads and mouse wheels), and gentle wheel zoom elsewhere. Pinch and Ctrl/⌘ + wheel zoom remain available; there is no input-mode switch. Mouse users can zoom with Ctrl/⌘ + wheel or the toolbar. Safari native gesture events are supported, with duplicate pinch wheel events suppressed. Zoom is bounded to 20–300%; toolbar zoom anchors at the viewport center. “适应” recenters/scales within those bounds, and the percentage button resets position and zoom. Canvas-focused arrow keys pan, +/- zoom and 0 resets. Pointer capture keeps releases outside the dialog safe; drag/pinch completion suppresses accidental node clicks. Gestures do not change the underlying reader or browser zoom, and do not call AI. Local/sample books require a cloud upload first.

## Source and limits

The client sends only the archive-relative navigation href, including fragment. The Worker reads the owned archive and resolves the same inferred Chinese chapter hierarchy as the TOC. A parent includes all descendants through the next entry at its own or a higher level. Section fragments are resolved against actual source IDs; a chapter may span multiple spine files. No retrieved top-k snippets, client-supplied book text, or silently truncated chapter excerpts are used. Missing anchors, backwards navigation, less than 30 characters and more than 100,000 characters fail before inference. For very long chapters the UI asks the reader to generate individual sections.

The prompt asks DeepSeek Flash for compact JSON (120 nodes, 5 levels below the root, 12 children per node). The parser normalizes missing/null leaf children, string leaves, text/label/name/title labels, a single root/mindmap/tree wrapper, and a complete JSON code fence. Defensive limits are separate: 512 nodes, 12 levels below root, 64 children per node, 1,000 characters per label, and 120,000 response characters. It rejects broken/truncated JSON instead of guessing missing content or dropping branches. The renderer uses React text nodes, not HTML or model-authored diagram code. Source text is explicitly untrusted data in the system prompt. The model can still summarize incorrectly; the dialog identifies the map as AI-generated.

## Persistence and duplicate prevention

Apply additive migration `0005_mindmaps.sql` before deploying. `mindmaps` has one primary-key row per user/book/target. An atomic insert or compare-and-set reserves a generation across Worker isolates and devices. Ready results have no TTL and are not invalidated by model/prompt updates. Reindexing an unchanged book preserves them. Book/user deletion cascades D1 results; book deletion also removes the private R2 recovery prefix.

`GET /api/books/:id/mindmap?target=...` reads status; `POST` with `{target}` generates only missing results. `{target,retry:true}` can retry a known failed attempt, but never regenerates a ready or running result. Authentication, current terms and book ownership are required. New attempts are limited to 6/minute and 40/day per account. Concurrent requests see `running` and poll reads, not inference. Closing a dialog keeps its existing fetch alive; opening it again checks the durable state.

The original HTTP request remains open during inference (90-second provider timeout). The Worker also attaches the work to waitUntil; this is not a durable background job. Platform termination or closing the entire browser can interrupt execution. A running row older than 150 seconds is shown as interrupted and is NOT automatically retried or lease-stolen, because the provider may already have charged. A future operator reconciliation should inspect the matching operation/usage rows before unlocking. The UI offers read-only status checks for this state.

A final D1 result-write failure falls back to a private R2 object. Reads recover that result without inference. A total storage/platform failure can still lose a completion; the durable admission row prevents a silent new paid call. Deletion races are checked before storing D1 results and after writing R2. If D1 is also unavailable during an R2 recovery/deletion check, the private object is retained; ownership checks prevent retrieval after deletion, and orphan recovery objects may require operator cleanup.

Complete responses that fail parsing/validation (within the response-size bound) are retained in a private `*.rejected.json` object alongside the operation ID and result metadata. Status reads can reparse a matching failed operation after a parser update and promote it to a saved result without inference. Results from a different operation cannot be recovered into the current attempt. These objects are not treated as ready by the TOC index and are removed with the book. Rejection logs contain only operation IDs, reason codes, size and retention status; detailed reason codes also enter the usage ledger. Older failures predating retention cannot be reconstructed from token counts alone.

## Tokens and costs

Each actual attempt uses `startAiCall` with feature `mindmap` and a unique operation ID. The durable started row is written before the paid request. Provider usage is observed before output validation, so truncated/invalid outputs and known failed calls retain reported tokens. No automatic provider retries or fallbacks occur. An explicit retry is a separate ledger row. Existing usage persistence retries and R2 recovery apply; unknown usage is unknown, not zero.

The cost panel labels these rows **章节思维导图**, showing reported input/output/cached-input tokens and the existing model pricing calculation. HTTP/D1/R2 operations are separately labeled **思维导图请求**. Reading a saved map does not create an AI usage row, but ordinary request/storage read costs still apply. Dollar figures remain public-list-price estimates, not invoices; storage and other existing exclusions still apply.

## Highlight mind maps

The highlight/underline toolbar offers a mind-map action. A completed map has a green checked icon and a “View highlight mind map (saved)” label. The same full-reader canvas, pan/zoom and expand/collapse controls apply. The original passage is available in a collapsible disclosure. Chinese and English interface labels are included.

Targets prefixed with `annotation:` identify a specific persisted annotation ID. Generation accepts only this ID, never passage text in the request. Before claiming a new job, the Worker queries the annotation by user, book and ID; its immutable stored `text` is the entire source (up to the annotation API's 20,000-character limit). Short non-empty highlights are allowed; the prompt asks for only supported branches rather than padding short excerpts. The browser flushes the annotation before opening a new map, so a newly created highlight can be used immediately. Missing or unsynced annotations fail before inference.

Existing atomic admission, failed-attempt handling, result persistence and R2 recovery apply unchanged. Each result also stores the annotation ID and quote snapshot. Results have no TTL, survive reloads/devices and style/note/tag changes, and are not regenerated on model updates. Deleting a highlight does not delete the paid result; deleting the book/account retains the normal deletion semantics. No database migration is needed: the existing user/book/target key stores both navigation and annotation targets separately.

Usage is recorded under `highlight_mindmap`, shown as **划线思维导图 / Highlight mind map** with provider input/output/cache tokens and priced cost components. Failed calls remain metered and explicit retries create separate usage records. Opening saved results never invokes inference. HTTP/storage reads still use the ordinary mind-map request meter.

Validation includes Worker tests for saved-source isolation, short excerpts, ownership, missing/empty input, concurrent admission, R2 recovery with the source snapshot, persistence, cache reuse and failure/token/cost accounting. `web/scripts/check-highlight-mindmaps.mjs` uses mocked API responses to exercise the real toolbar and canvas, annotation sync ordering, rapid reopen, fresh-page restore, independent highlights, changed colors/styles, both languages and narrow screens without paid calls.
