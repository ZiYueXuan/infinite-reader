# Chinese and English interface

The interface supports `zh-CN` and `en`. Signed-out readers can choose a language in the sign-in card or offline account capsule. Signed-in readers use the language selector in the account capsule menu on both the shelf and reading page.

The first visit follows the browser language (Chinese variants use simplified Chinese; other languages fall back to English). An explicit `?lang=zh-CN` / `?lang=en` takes precedence, followed by the `ir_locale` preference cookie and `ir:locale` local storage. The cookie lets the server render `/about`, `/privacy` and `/terms` in the same language. Changing language updates `document.lang`, persists the preference, and synchronizes open tabs via the storage event. Public pages include their own language links and use private, non-cacheable responses to prevent mixing language variants.

## Translation boundaries

- `shared/messages.json` holds source-copy keys and `[Chinese, English]` pairs. Positional `{0}` placeholders are interpolated as plain text. `shared/i18n.ts` is usable in both browser and Worker code.
- `web/src/i18n/runtime.ts` owns the browser preference, translations, locale-aware links, and safe error fallbacks. `index.ts` adds React subscriptions (`useLocale` / `useT`). Non-React code and the OffscreenCanvas worker import the pure runtime.
- `App` subscribes once for the normal component tree. Memoized translation-dependent components use `useT`; never capture translated labels in module-level constants. Font, theme, and color catalogs retain stable IDs and translate their labels only at display time.
- Language changes repaginate note placeholders and rebuild page textures around the current passage. The page-render worker receives the locale explicitly. Annotation source offsets, fonts, colors, tags, contents and generated AI results are not rewritten.
- Book titles, authors, metadata values, original passages, user notes/tags, AI answers, mind map nodes and map place names remain content in their original language. Only interface labels, built-in suggestions, status/error messages and cost explanations are translated. Switching language does not request AI generation.
- Server cost records remain canonical; the UI translates labels, units and explanations, including previously saved/interpolated messages. Raw exported diagnostic JSON and raw bibliographic records retain their original schema and values.
- The published Terms of Use snapshot and accepted version are unchanged. Public pages select the existing English or Chinese agreement section. The privacy page discloses the language preference storage in both languages.
- `/fonts/licenses.html` is a Vite HTML entry using the same catalog and preference. Official font license files retain their original legal text.

## Adding interface copy

Add both translations and identical placeholder sets to `shared/messages.json`, then call `t(key, ...values)` at rendering time. Keep complete sentences together when argument order or plural forms differ. For React memoization, use `useT()` and include its callback in dependencies. Never translate enum values, CSS classes, storage identifiers, user content, or model output.

## Checks

```sh
node web/scripts/check-i18n-source.mjs
npm --prefix worker test -- test/i18n.test.ts
npm --prefix web run build
npm --prefix web run lint
npm --prefix worker run typecheck
```

`web/scripts/check-i18n.mjs` exercises the API-mode frontend with mocked service responses and a real Chromium browser. Set `PUPPETEER_CORE`, `CHROME_BIN` and `READER_URL` as needed. It covers browser detection, persisted choice, live switching, forms/drafts, metadata, cost items, memoized Markdown, mind maps, canvas notes, tags, highlight controls, font licenses, mobile layout and preservation of original content. No real user data or paid AI calls are used.
