# Phone reading

Phone browsers and compact iPads (including iPad mini) automatically use a single page covering the available browser viewport. The same gestures, curl, controls, selection and progress logic serve both. iPads use a screen short edge of at most 800 CSS pixels, including Mac-style desktop user agents with multi-touch support. This is a layout category, not an exact model detector: iPads with the same logical screen dimensions share the experience. Screen dimensions keep the mode stable across rotation, split view and trackpad use; larger iPads, Android tablets and desktop computers retain the desk. Browser address bars are controlled by the browser, not by the reader. `viewport-fit=cover`, dynamic viewport height and safe-area insets protect text around notches and home indicators.

The existing pagination, source offsets, canvas textures, native text layer, annotations and `BookModel` are reused. Mobile pagination has equal side margins, a readable 20px default, adjustable 16–28px text, and no blank spread padding. Each mobile leaf represents one page. A rolling cylindrical fold keeps untouched text flat, follows horizontal finger travel, and tilts with the touch position. The verso shows faint, mirrored ink from the same page. A top-down camera frames only the right page, while the desk, binding and page-block furniture are hidden. Desktop `LeafSim` geometry and two-page numbering are unchanged.

- Swipe left/right or tap the outer 22% to turn one page. Interrupted touches and second fingers cancel the held sheet. The first and last pages are bounded; backward navigation never closes the mobile book.
- The first 12px establish horizontal intent without lifting the page. After that, the fold follows the pointer without a spring. A drag of 28% of the screen width or a deliberate flick commits; a reverse flick cancels. Release settles in 180–300ms. Progress and contents seeking selects the target directly rather than fanning multiple sheets.
- Tap the center or page counter to show reading controls. Contents, progress, AI and font settings remain available. Persistent desktop launchers are hidden while reading.
- Long press a word to select source text; keep holding and drag to extend the passage. Only the selection highlight follows the finger; annotation actions appear after release. Interrupted touches and second fingers clear the provisional selection without opening a toolbar. Phone selection uses source offsets and a reader-painted highlight instead of a browser Range. Native text callouts, selection and context menus are disabled on phone book text, while editors and desktop selection retain normal browser behavior. Inline notes, images and footnotes keep their existing source-based behavior; annotation actions wrap on narrow screens.
- During selection, hold in the page's lower-right corner for 500 ms to turn one page, then move into the new text to continue the same passage. The corner cannot repeatedly turn pages while the finger stays still. Lifting during the animation opens tools after settling with the last confirmed source range. Selection stops explicitly at the chapter boundary. See `cross-page-selection.md` for the shared selection controller and touch regression.
- Rotation, viewport changes and text size changes repaginate around the source passage. Keyboard/editor input does not initiate viewport reflow. Note reflow uses the current viewport when editing finishes.
- Viewport reflow requests are retained during loading or text entry and replayed when loading/editing ends or focus leaves the editor. Range controls do not block reflow. Rotation, visual-viewport changes and app resume remeasure the container, including bounded settling probes for standalone WebKit; late book/font results are checked against the current viewport before leaving an outdated page shape on screen.
- The existing cloud `lastLeaf` field retains desktop-pagination semantics. Phone progress is mapped through the original passage to the desktop pagination. A device-local, account-scoped source position provides precise phone reopening when the cloud leaf still agrees; it is ignored when cloud progress differs. No API or database migration is needed.

Validation:

```sh
cd web
node --experimental-strip-types --test src/book/phoneLayout.test.ts src/engine/phoneGestures.test.ts src/engine/reflowTarget.test.ts
VITE_BACKEND=local npm run dev -- --host 127.0.0.1 --port 5198
# In another terminal, provide the installed Puppeteer and Chrome paths:
PUPPETEER_CORE=<module-path> CHROME_BIN=<chrome-path> node scripts/check-phone-reader.mjs
```

The browser regression covers actual touch dragging/cancellation, forward/backward turns, long-press selection, inline note editing, narrow layouts, rotation, font-size reflow, reload progress, book boundaries, an English Android viewport and the desktop spread. Screenshots default to `/tmp/infinite-reader-phone`; `SCREENSHOT_DIR` and `READER_ORIGIN` override those locations. Use an isolated local-mode server, since the script creates a sample note in its fresh browser profile.

`scripts/check-ipad-mini.mjs` verifies iPad mini mobile/desktop user agents, viewport-filling pages, touch curls, readable contents, text size, rotation and split-view progress restoration. It also checks that larger iPads in split view and non-touch Macs retain the desk. Use `READER_DEVICE=ipad-mini` with `scripts/check-phone-cross-selection.mjs` to run the same cross-page gesture, persistence and cancellation suite at iPad mini dimensions. Both scripts accept the browser and local-server variables above; iPad screenshots default to `/tmp/infinite-reader-ipad-mini`.

`scripts/check-reader-rotation.mjs` checks repeated round trips, loading and keyboard deferral/replay, focused range controls, stale first viewport measurements, late layout commits and resume events. It asserts projected paper edges as well as pagination dimensions so a centered landscape sheet in a portrait viewport cannot pass. The standalone flag and delayed measurements are simulated; this does not replace a home-screen test on an actual iPad.

`scripts/check-phone-page-identity.mjs` uses the same environment variables and a 1,600-page fixture built from the local sample. It compares actual GPU pixels against the exposed page rendered alone, then checks real touch press/jitter, drag texture identity, cancellation, consecutive forward/backward swipes, vertical movement, edge/center taps, overlapping touches and multitouch cancellation. This catches visual page substitution that page-index assertions alone miss.

Phone resting pages use a fixed plane and only the exposed right sheet is drawn, alongside any sheet in flight. Rendering three compressed resting layers made their depth values indistinguishable in long books: lower-page ink could replace the current page until a drag lifted it. Desktop stacks retain their three layers. Touches starting during a landing animation do not queue a second turn when released.

`scripts/check-phone-curl.mjs` checks pointer-to-fold tracking, flat text geometry, stationary holds, pullback, short-drag cancellation, bounded release time, backward dragging and exact progress seeking. `src/engine/phoneCurl.test.ts` checks the geometry endpoints, edge travel, diagonal fold normals and release decisions. The reference screenshot informs the visual design; release timing is tuned for this reader, not measured from the reference app.

`scripts/check-phone-selection.mjs` checks real long-press/drag selection, native-menu suppression on book text, exact underline source ranges, note-editor native menus, passage handoff to AI, and desktop selection boundaries. It uses an isolated local sample and never sends an AI request.
